Here’s a clean graph schema design for StartupConnect.

🧩 Vertex Types (Nodes)
These are the core entities in the ecosystem graph.

1️⃣ User
Represents any individual on the platform.

Label: User

Properties

user_id (PK)

name

role_primary (founder / investor / operator)

roles_secondary (array)

domain_tags (AI, fintech, SaaS…)

geography

experience_years

reputation_score

verification_status

created_at

👉 One person can have multiple roles.

2️⃣ Startup
Represents companies.

Label: Startup

Properties

startup_id (PK)

name

domain

stage (idea / MVP / seed / seriesA…)

geography

founded_year

funding_status

employee_count

visibility_level (public / trusted_only)

3️⃣ Organization
Accelerators, VC firms, incubators, scout orgs.

Label: Organization

Properties

org_id (PK)

name

type (VC / accelerator / incubator / angel network / law firm)

geography

domains

website

4️⃣ Post (Optional but useful node)
Structured ecosystem signals.

Label: Post

Properties

post_id

post_type (fundraising / hiring / launch / thesis)

visibility_scope

created_at

🔗 Edge Types (Relationships)
This is the most important part of your system.

All edges should include shared metadata:

Common Edge Properties

trust_score (0–1)

strength_score (0–1)

recency_score (0–1)

interaction_count

successful_intros

last_interaction_at

created_at

👥 USER ↔ USER EDGES
1️⃣ TRUSTS
One‑way trust relationship.

Edge: TRUSTS
User ➜ User

Meaning:

“I trust this person to make introductions.”

Properties:

trust_score

endorsement_count

domain_tags

If mutual → becomes strong connection in ranking.

2️⃣ INTRODUCED
Tracks real intro events.

Edge: INTRODUCED
User ➜ User

Properties:

intro_count

success_rate

last_intro_at

Feeds trust scoring.

3️⃣ WORKED_WITH
Professional collaboration.

Edge: WORKED_WITH

Properties:

company_name

duration_months

collaboration_strength

4️⃣ ENDORSED
Skill/domain endorsement.

Edge: ENDORSED
User ➜ User

Properties:

domain_tag

weight

👤 USER ↔ STARTUP EDGES
5️⃣ FOUNDED
Founder relationship.

Edge: FOUNDED
User ➜ Startup

Properties:

role (cofounder / founder)

start_date

active (bool)

6️⃣ WORKS_AT
Employment.

Edge: WORKS_AT
User ➜ Startup

Properties:

role_title

start_date

end_date

7️⃣ ADVISOR_TO
Advisor / mentor.

Edge: ADVISOR_TO

Properties:

advisory_strength

active

💰 USER ↔ STARTUP (Investor Relationships)
8️⃣ INVESTED_IN
Investor → startup.

Edge: INVESTED_IN
User ➜ Startup

Properties:

round (angel/seed/seriesA…)

amount_range

year

visibility (public / trusted_only)

⚠️ Important feature from your spec.

9️⃣ INTERESTED_IN
Soft investor interest signal.

Edge: INTERESTED_IN
User ➜ Startup

Properties:

interest_level

created_at

🏢 USER ↔ ORGANIZATION EDGES
🔟 MEMBER_OF
User part of VC firm / accelerator.

Edge: MEMBER_OF

Properties:

role (partner / scout / associate)

start_date

1️⃣1️⃣ AFFILIATED_WITH
Loose association.

Mentor / speaker / alum.

📢 POST RELATIONSHIPS
1️⃣2️⃣ CREATED
User ➜ Post

1️⃣3️⃣ ABOUT
Post ➜ Startup / Organization

1️⃣4️⃣ INTERESTED_IN_POST
User ➜ Post

Investor expresses interest.

⭐ SPECIAL EDGE (CORE FEATURE)
1️⃣5️⃣ INTRO_PATH
Created only during intro workflow.

User ➜ User chain edges created temporarily or stored historically.

Properties:

path_score

hop_count

status (pending / completed / failed)

This becomes training data for trust scoring.

🎯 How This Supports Your Core Logic
Your intro path query becomes:

Founder → TRUSTS → TRUSTS → MEMBER_OF → INVESTOR
Founder → TRUSTS → WORKED_WITH → INVESTOR
Founder → TRUSTS → ADVISOR_TO → INVESTOR

Graph traversal depth: max 4 hops
